Portfolio Interview Agent

GitHub Pages의 정적 포트폴리오와 private gateway의 질의 이해·근거 검색·생성을 분리하고, 프로젝트·기술·경험·가치관을 질문 가능한 인터페이스로 연결한 AI 인터뷰 서비스

프로젝트 개요

포트폴리오는 모델이 없어도 끝까지 읽을 수 있어야 하지만, 면접관이 확인하려는 지점은 역할·설계 판단·한계처럼 질문마다 달라집니다. 이 프로젝트는 일반 포트폴리오 탐색을 본체로 유지하면서, 질문 범위와 대화 의존성을 먼저 해석하고 필요한 프로젝트 근거와 승인된 판단 지식을 찾아 답변하는 선택형 인터뷰 경험을 추가했습니다. 정적 화면은 GitHub Pages에서 제공하고 AI 요청만 ngrok HTTPS endpoint를 통해 private Node gateway와 Ollama로 전달합니다.

구분 내용
적용 대상 기술 포트폴리오를 검토하는 채용 담당자·면접관
입력 자연어 질문, 검증된 페이지 문맥, 필요한 경우에만 조회한 대화 메모리
활용 정보 공개 경력·프로젝트·설계 근거와 agent-only Gold 판단 passage
출력 근거 범위 안의 스트리밍 답변, 공개 source, 최대 2개의 후속 질문, 실행 trace 또는 HITL
배포 환경 GitHub Pages frontend → ngrok HTTPS → Node gateway → private Ollama

읽기와 질문을 함께 두는 화면

기본 경로는 Landing → Selected work → Project → Claim/source record → Results & limits입니다. AI 인터뷰는 이 경로를 대신하지 않고, 현재 페이지에서 바로 질문한 뒤 답변과 공개 근거 기록을 연결하는 보조 경로입니다.

데스크톱에서는 대화, 실행 단계, 근거 Inspector를 하나의 workspace에서 보고, 모바일에서도 답변 아래에서 source를 확인할 수 있습니다. Trace는 최초 DOM을 유지한 채 단계 상태만 갱신하고, 답변이 길어 두 번째 생성으로 이어질 때는 continuation 상태와 경과 시간을 즉시 보여줍니다. 브라우저를 새로고침해도 완료된 대화와 session ID를 제한적으로 복원하며, 모델이 오프라인이어도 프로젝트 본문은 그대로 읽을 수 있습니다.

질문에서 근거가 있는 답변까지

0.0.4는 모든 질문을 곧바로 자유 Agent 탐색에 맡기지 않습니다. 질의 이해 단계에서 대화 의존성, scope와 답변 authority를 정한 뒤 검증된 preset으로 검색·생성 범위를 제한합니다.

단계 처리 내용
참조 신호 확인 “첫 질문”, “방금 답변”, “세 번째 질문”처럼 명백한 시간·순서 참조를 LLM 전에 판정
질의 이해 250개 승인 scope exemplar의 sparse·BGE-M3 검색과 Gemma 분류를 결합해 general·portfolio·personal·hybrid 범위 결정
대화 메모리 필요한 경우에만 first, last, previous, ordinal, semantic, outline selector로 최대 3개 turn 조회
HITL 참조 대상을 찾지 못하거나 답변 authority가 달라지는 모호성은 추측하지 않고 두 선택지로 확인
preset routing prepared, project fact, technical deep dive, cross-project judgment, personal principle, generic retrieval 등 검토된 workflow 선택
근거 검색 프로젝트 evidence를 사실·citation 정본으로 검색하고, 필요할 때만 승인 Gold passage 1개를 판단 이유·조건 보강에 사용
답변 생성 공유한 BGE-M3 query embedding과 compact prompt를 사용해 최대 480토큰 생성, 길이 종료일 때만 1회 이어쓰기
근거 검증 실제로 회수된 public allowlist source만 사용자 citation으로 반환

프로젝트 관련 멀티턴 질문도 대화 메모리만으로 답하지 않습니다. 참조 대상을 복원한 뒤 프로젝트 evidence를 새로 검색합니다. 과거 Assistant 답변과 Gold는 질문 이해와 판단 보조 근거이며 프로젝트 사실의 authority나 공개 citation이 아닙니다.

공개 projection과 근거 계보

원본 이력서·경력기술서·프로젝트 문서와 Personal Wiki를 그대로 배포하지 않습니다. 공개할 주장과 원본 section binding을 projection 선언에 기록하고, 빌드가 실제 section·신뢰 상태·digest를 확인한 뒤 data/knowledge.json을 생성합니다.

계층 역할
원본 프로젝트 문서 역할·구조·확인된 결과의 authority
공개 projection 공개할 node·요약·관계와 원본 section binding
curated Gold 9개 문서를 78개 passage로 분해한 agent-only 판단 렌즈
빌드·감사 source 존재, digest, 참조 정합성, 절대 경로·private locator 누출 검사
공개 지식 번들 browser·fallback·gateway가 공유하는 allowlist 근거
답변 source 실제로 선택된 public node를 claim/source record로 연결

Gold는 “왜 그런 판단을 했는가”를 보강하지만 원문·ID·locator·검토 기록은 browser와 citation에 포함하지 않습니다. 관계 그래프도 검색 후보를 넓히는 경로일 뿐 새로운 경력 사실을 만들거나 source authority를 높이지 않습니다.

배포 환경과 레이턴시 최적화

사용자가 접속하는 서비스 경계는 GitHub Pages와 ngrok입니다. GitHub Pages는 정적 HTML·CSS·JavaScript와 공개 지식만 제공하고, 질문은 ngrok HTTPS → Node gateway → Ollama 순서로 전달됩니다. gateway는 기존 0.0.3 frontend의 v1 계약과 0.0.4의 v2 preset 계약을 함께 지원합니다.

로컬 모델의 긴 prefill과 생성 시간이 병목이므로, 답변 의미를 바꿀 위험이 낮은 단계만 캐시하거나 사전 계산했습니다.

최적화 적용 방식
준비 답변 검토된 소개 질문의 exact alias만 bundle digest와 source allowlist 검증 후 모델 호출 없이 반환
scope index 250개 exemplar의 sparse index와 BGE-M3 dense index를 오프라인에서 생성해 질의 이해 prior로 사용
공유 embedding 질문 embedding을 scope·project·Gold 검색에서 요청당 최대 1회 공유
분류 cache query type index·model·schema digest가 같은 성공 분류만 최대 256개·2시간 재사용
출력 상한 일반 생성은 최대 480토큰, length 종료일 때만 반복 없는 이어쓰기 1회
후속 질문 추가 LLM 호출 없이 실제 plan·evidence와 연결된 질문만 최대 2개 선택
브라우저 상태 완료 대화와 session ID를 2시간·20개 또는 256KB 안에서 sessionStorage에 보존
스트리밍 UX Trace 단계 pacing은 유지하면서 구조적 재렌더링을 없애고 실제 수신 답변 일부와 continuation 상태 표시

의미가 비슷하다는 이유만으로 임의 답변을 재사용하는 semantic answer cache는 두지 않았습니다. 일반 질문은 계속 retrieval과 LLM 생성을 거치며, timeout 결과나 HITL은 cache하지 않습니다. ngrok·gateway·Ollama 장애에 한해서만 browser가 같은 공개 지식 번들을 사용하는 결정적 fallback으로 전환합니다.

대화 메모리와 현재 화면 문맥

0.0.4는 같은 주제라는 이유만으로 최근 대화 전체를 prompt에 넣지 않습니다. 먼저 질문을 independent, conversation-required, page-required, unresolved로 분류하고, 실제 참조가 필요한 경우에만 bounded memory tool을 호출합니다.

명백한 시간·순서 참조는 결정적으로 정확한 turn을 찾고, 의미 기반 회상은 최대 3개 후보만 전달합니다. 메모리 도구가 대상을 찾지 못하면 임의의 과거 turn에 연결하지 않고 HITL로 전환합니다. 브라우저 transcript는 새로고침 후 화면을 복원하지만 server session이 만료되면 AI 문맥은 새로 시작됐음을 표시합니다.

페이지 문맥도 client가 보낸 제목이나 ID를 그대로 신뢰하지 않습니다. route type과 entity ID를 공개 catalog에서 다시 계산하고, 프로젝트 질문이면 대화 메모리와 별개로 최신 public evidence를 다시 검색합니다.

실행 상태와 관측

v2 Trace는 Context → Query understanding → Preset → Evidence → Judgment → Synthesis → Source check를 표시합니다. 단계별 pacing UX는 유지하지만 panel DOM을 교체하지 않아 탭·스크롤·focus가 보존됩니다. 생성 중에는 실제로 수신된 답변의 일부를 보여주고, 이어쓰기 pass가 시작되면 두 번째 token 전에도 활성 상태와 경과 시간을 표시합니다.

Langfuse exporter는 선택형 관측 경로입니다. query scope 분류, 답변 생성과 continuation을 분리해 model·cache hit·token·TTFT·done reason을 기록하지만 exporter 실패는 답변을 막지 않습니다. 질문·답변을 외부로 보내기 전 민감 패턴을 마스킹하며, production privacy·retention 검토가 완료됐다고 주장하지 않습니다.
