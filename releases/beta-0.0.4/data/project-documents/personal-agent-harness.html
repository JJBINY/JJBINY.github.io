Personal Agent Harness

여러 AI Agent가 과거의 결정, 검증된 설계와 작업 지침을 잃지 않고 다음 작업의 맥락과 실행 절차로 다시 사용하게 만드는 개인 AI 협업 시스템

프로젝트 개요

AI와 반복해서 일하면서 좋은 설계 판단, 사용자 교정, 실패를 통해 만든 지침이 대화가 끝날 때 함께 사라지는 문제가 있었습니다. 다음 Agent는 같은 용어를 다시 정하고, 이미 검토한 선택지를 다시 비교하며, 한 번 해결한 실수를 반복했습니다.

이 프로젝트는 그런 경험을 Personal Wiki의 검토 가능한 지식과 Skill의 실행 절차로 축적하고, 작업이 시작될 때 필요한 맥락과 절차를 자동으로 선택해 Agent에게 제공합니다. 동시에 하나의 원본 저장소와 통합 설정을 기준으로 Codex, Claude Code, Gemini의 기능을 구성하고 상태 차이를 점검합니다.

적용 대상 Codex, Claude Code, Gemini 기반 개인 AI 작업 환경
관리 정보 작업 절차(skill), MCP 도구, 데이터 접근 정책, 개인 지식, 결정 기록

전체 시스템 아키텍처

설명 모델 — 현재 저장소의 통합 설정, 실행 패키지, Agent별 설정 반영 관계를 포트폴리오용으로 단순화한 그림

저장소는 수정해야 할 원본과 실행 패키지를 보관합니다. 작업 시작 시 Personal Wiki가 관련 용어·결정·사례를 제공하고 Skill Router가 상황에 맞는 절차를 선택합니다. 중앙 관리 모듈(Harness Core)은 이 기능들을 각 Agent가 사용할 수 있는 형식으로 반영하고 실제 환경과 원본 사이의 차이를 점검합니다.

Wiki–Skill 협업 루프

대화와 프로젝트에서 나온 결정·교정·사례는 바로 영구 규칙이 되지 않습니다. 관찰과 초안으로 수집한 뒤 검토 상태를 높이고 검색 인덱스에 반영합니다. 새 작업에서는 사전 조회가 현재 과제에 맞는 지식만 선택하며, skill_refs는 설치·지원·trigger 조건이 맞는 Skill에만 연결됩니다.

계층 담는 내용 작업에서의 사용
Personal Wiki 용어, 선호, 결정, 설계 근거, 실패·성공 사례 왜 그렇게 판단하는지와 프로젝트 맥락 제공
Skill 반복 가능한 절차, 검사 순서, 도구 사용과 안전 경계 지금 무엇을 어떤 순서로 수행할지 제공
Manifest canonical source, 대상 Agent, 도구·데이터 권한 어떤 기능이 실제 설치·실행 가능한지 결정
Outcome 기록 적용한 지식, 도움 여부, 결함과 후속 조치 다음 조회와 Skill 개선의 근거

Wiki는 지식이고 Skill은 실행 절차입니다. 예를 들어 “비표준 용어 때문에 협업이 흔들렸다”는 사례와 선호 용어는 Wiki에 남고, 문서·코드·대화에서 용어를 수집하고 충돌을 판정하는 단계는 align-terminology Skill로 남습니다. 둘을 같은 거대한 prompt에 고정하지 않고 작업마다 필요한 조합을 선택합니다.

Personal Wiki 등록과 조회

흐름 단계 결과
등록 대화·결정·사례 수집 → observation·draft → 사람의 검토·승격 → reviewed·verified 재사용 가능한 Markdown·YAML 지식과 검색 인덱스
조회 작업 사전 조회 → keyword·semantic·status·환경 조건 적용 → selected·excluded 분리 현재 작업에 사용할 context와 보류할 후보
실행 연결 구조화된 skill_refs 확인 → 설치·Agent 지원·trigger 검증 실행 가능한 Skill만 작업 계획에 포함
학습 완료 후 helpful·unused·defect outcome 기록 지식 품질과 다음 검색 개선 근거

Skill군과 상황별 Trigger

Skill은 도구 목록이 아니라 반복해서 겪은 문제를 실행 가능한 작업 방식으로 만든 단위입니다. 사용자의 명시적 호출, 요청의 작업 유형, 저장소 상태와 위험 조건을 trigger로 사용합니다.

Skill군 대표 상황과 예시 Trigger와 대응
용어·글쓰기 Agent마다 다른 용어·문체, 설명의 과잉·모호함 문서 작성·교정 요청에서 용어 정렬과 독자 중심 서술 적용
코드 설계 도메인 경계, 낮은 응집도, 높은 결합도, interface·algorithm 판단 비단순 구현·리팩터링에서 DDD, 객체·함수 설계, review 기준 선택
시각화·문서 같은 구조를 여러 diagram tool로 중복 제작 관계와 독자에 맞춰 architecture·flow·sequence·ER type과 산출 형식 선택
데이터·모델링 분석·통계·ML 작업의 방법과 검증 혼재 데이터 profile, 통계 설계, 분류·평가 단계와 증거 수준 분리
운영·통합 여러 Agent 설정 차이, 외부 도구 승인과 설정 충돌 manifest 검증, projection, status, 승인 경계와 안전한 reconcile

작업마다 모든 Skill을 넣지 않습니다. 현재 과제에 맞는 Skill군만 선택해 context를 작게 유지하고, 동일한 검토 기준을 여러 Agent에서 재사용합니다. 생산성 향상은 “더 많은 prompt”보다 이미 해결한 판단을 다시 찾고 같은 출발 절차를 반복하지 않는 데서 발생합니다.

AI와의 협업 방식

이 하네스에서 AI는 매번 처음 만나는 범용 도구가 아니라, 검토된 개인 맥락과 작업 절차를 공유하는 협업자에 가깝습니다. Wiki는 과거 판단의 이유와 사례를 제공하고 Skill은 실행과 검증 방식을 제한하며, Outcome 기록은 이번 적용이 실제로 도움이 됐는지 다음 작업에 돌려줍니다.

  • 새로운 문제: Agent와 함께 해결하고 판단·실패·교정을 기록
  • 반복 가능성 확인: 지식은 Wiki, 절차는 Skill, 설치 계약은 Manifest로 분리
  • 다음 작업: 사전 조회와 trigger로 필요한 부분만 다시 사용
  • 결과 검토: 증거, 변경 범위, 사용자 교정을 Outcome과 결정 기록에 반영

이 구조를 통해 여러 Agent를 사용해도 선호 용어, 설계 원칙, 코드리뷰 방침과 시각화 기준을 매번 처음부터 설명하지 않고 같은 협업 계약 위에서 작업할 수 있습니다.

통합 관리 기준

통합 설정 파일(harness/manifest.yaml)은 Agent, 작업 절차, MCP 도구, 데이터 접근 범위를 등록하는 기준입니다. Wiki 문서에 도구가 언급되어 있더라도 통합 설정에 등록되고 검증되기 전에는 실행 가능한 기능으로 취급하지 않습니다.

관리 대상 통합 설정에 포함되는 정보
Agent 대상 이름, 설정 위치, 지원 기능
작업 절차 원본 위치, 적용 대상, 설명 정보
MCP 도구 실행 명령, 인자, 환경 요구, 적용 대상
데이터 소스 소유 범위, 저장 위치, 읽기·쓰기 정책

주요 구성요소

구성요소 역할
중앙 관리 모듈(Harness Core) 통합 설정 해석, 기능 목록 계산, Agent 환경 비교
설정 반영(Reconcile) 생성·갱신·충돌 계획 작성과 실제 적용

Agent별 설정 반영

Agent 작업 절차 MCP 도구
Codex 원본 skill 연결 Codex 형식의 server 설정
Claude Code 원본 skill 연결 Claude Code 형식의 server 설정
Gemini 별도 skill directory 연결 없음 Gemini 형식의 server 설정

모든 Agent에 같은 파일 구조를 강제하지 않고, 각 Agent가 실제로 지원하는 범위만 통합 설정에 기록합니다. 같은 작업 절차를 여러 위치에 복사하지 않고 원본에 연결해 버전 차이를 줄입니다.

설정 반영 흐름

  1. 통합 설정 확인 — 등록된 Agent, 작업 절차, 도구, 데이터 소스를 검증합니다.
  2. 현재 상태 비교 — Agent 환경의 파일 연결과 MCP 설정을 확인합니다.
  3. 변경 계획 작성 — 생성, 갱신, 충돌 항목을 적용 전에 보여줍니다.
  4. 설정 반영 — 파일 잠금과 안전한 쓰기 방식으로 변경합니다.
  5. 결과 점검 — 원본과 Agent 환경의 차이가 해소됐는지 다시 확인합니다.

지식과 실행 설정의 분리

Personal Wiki는 Agent가 판단에 활용할 지식과 선호를 제공합니다. 실제 파일 생성과 도구 설치는 통합 설정과 검증된 원본만을 기준으로 수행합니다. 검색된 문장이 실행 설정으로 자동 변환되는 경로를 두지 않습니다.

데이터와 보안 경계

저장소에 포함 로컬 또는 별도 보관
통합 설정, 코드, 작업 절차 원본 비밀번호, 토큰, 인증 상태
결정 기록, 재현 가능한 문서 원시 대화 이벤트, 임시 로그
검증 가능한 패키지 구성 캐시, 생성 인덱스, 애플리케이션 상태

데이터 소스에는 개인·프로젝트·조직·공개 범위와 로컬·원격 저장 위치를 함께 기록합니다. 읽기, 쓰기, 승인 필요, 초안 전용 같은 접근 정책도 기능 설정과 함께 관리합니다.
